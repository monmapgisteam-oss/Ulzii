# Ургамлан нөмрөгийн хээрийн судалгааны мэдээллийн сан

Нөхөн сэргээлтийн дараах ургамлан нөмрөгийн байдлын үнэлгээний хээрийн судалгааны
мэдээллийг **ArcGIS Feature Service**-ээс шууд уншиж, нэг дэлгэцэнд багтаасан
орон зайн шинжилгээ, тайлагналын систем. Next.js (App Router) дээр боловсруулав.

## Мэдээллийн эх сурвалж

Толгой хэсгийн товчоор **хоёр төслийн** мэдээллийн санг сэлгэнэ:

| Төсөл | FeatureServer |
| ----- | ------------- |
| **Post rehab** | `…/service_99d12031bc274b73af81b5e00b05d63f/FeatureServer` |
| **Rangeland** | `…/service_a3e5e179afc84eebbfb2540977417ab9/FeatureServer` |

(суурь хаяг: `https://services-ap1.arcgis.com/fwC6eN4IwtqH3A7R/arcgis/rest/services/`)

Хоёулаа ижил гурван давхаргатай боловч талбарын нэршил ялгаатай тул төслийн
схемийг [src/lib/projects.ts](src/lib/projects.ts) файлд тодорхойлов:

| | Post rehab | Rangeland |
| --- | --- | --- |
| Ангилал | `treatment` (Post rehab / Control) | `biome`, `bag` |
| Талбайн нэр | `area_id` | `plot_id_name` |
| LP шугам | `line_2` | `line` |
| Эх талбайн код | `parent_id_10` / `parent_id_LP` | `parent_plot_id` |
| Хэмжээ | 119 талбай · 1,384 бичиглэл · 56,638 LP цэг | 75 талбай · 650 бичиглэл · 33,907 LP цэг |

Шүүлтүүр, график, газрын зургийн тэмдэглэгээ, хүснэгтийн багана бүгд уг схемээс
уншдаг тул төсөл солиход интерфэйс автоматаар тохирно.

| Дугаар | Давхарга / хүснэгт | Агуулга |
| ------ | ------------------ | ------- |
| 0 | `survey` (цэгэн давхарга) | Судалгааны талбайн үндсэн бүртгэл — байршил, огноо, байгалийн бүс, хувилбар, өндөр, бүртгэгч |
| 1 | `bichiglel` (хүснэгт) | **10 минутын бичиглэл** — талбай тус бүрт 10 минутын хугацаанд бүртгэсэн ургамлын зүйлийн жагсаалт |
| 2 | `lpdata` (хүснэгт) | **LP data** — шугам-цэгийн (line-point intercept) хэмжилт, 4 шугам × 120 цэг, 0.25 м алхамтай |

Хүүхэд хүснэгтүүд нь `parentglobalid` талбараар `survey` давхаргын `globalid`-тай
холбогдсон (нэгээс олон харьцаа).

## Тохиргоо

Сервис нь **editor tracking + ownership access control** идэвхжсэн тул нэр нууцгүй
хандалтад бичлэг буцаадаггүй. Иймд итгэмжлэлээ `.env.local` файлд тохируулна:

```bash
cp .env.local.example .env.local
```

```env
ARCGIS_USERNAME=таны_нэвтрэх_нэр
ARCGIS_PASSWORD=таны_нууц_үг
```

Эсвэл `ARCGIS_CLIENT_ID` / `ARCGIS_CLIENT_SECRET` (OAuth 2.0), эсвэл бэлэн
`ARCGIS_TOKEN` ашиглаж болно. **Токен зөвхөн серверийн талд ашиглагдах бөгөөд
хөтөч рүү дамждаггүй.**

## Ажиллуулах

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start   # бүтээгдэхүүний хувилбар
```

Итгэмжлэл бэлэн болоогүй үед интерфэйсийн загварыг харах бол:

```bash
DEMO_DATA=1 npm run dev
```

Энэ үед зөвхөн **бодит бус демо өгөгдөл** ачаалагдах бөгөөд толгой хэсэгт
«ДЕМО ӨГӨГДӨЛ (бодит бус)» гэсэн шар анхааруулга харагдана.

## Vercel дээр байршуулах

1. [vercel.com](https://vercel.com) → **Add New… → Project** → GitHub-аас `monmapgisteam-oss/Ulzii`
   репозиторийг импортлох (Next.js-ийг автоматаар таних тул build тохиргоо шаардлагагүй).
2. **Environment Variables** хэсэгт дараахыг нэмнэ:

   | Нэр | Утга |
   | --- | --- |
   | `ARCGIS_USERNAME` | ArcGIS Online хэрэглэгчийн нэр |
   | `ARCGIS_PASSWORD` | нууц үг |
   | `ARCGIS_REFERER` | `https://<төслийн-нэр>.vercel.app` |

3. **Deploy** дарна. Серверийн функцууд Сингапурын бүсэд (`sin1`) ажиллана —
   ArcGIS-ийн `services-ap1` сервертэй ойр тул хариу хугацаа богино.

> **Анхаар:** апп нь хэрэглэгчийн өмнөөс ArcGIS-д нэвтэрч өгөгдлийг уншдаг тул
> нээлттэй байршуулбал холбоос мэдсэн хэн ч мэдээллийг харна. Vercel-ийн
> *Settings → Deployment Protection* хэсгээс нууц үгийн хамгаалалт тавихыг зөвлөнө.

## Үндсэн боломж

1. **Нэг дэлгэцийн зохион байгуулалт** — хуудас гүйлгэхгүй (100dvh). Газрын зураг,
   график, хүснэгт тус бүр дотроо гүйдэг.
2. **Шүүлтүүрийг өгөгдлийн сангийн талд хэрэглэнэ** — сонгосон нөхцөл бүр ArcGIS
   `WHERE` илэрхийлэл болон хөрвөж, FeatureServer рүү дамжина. Идэвхтэй илэрхийлэл
   газрын зургийн толгойд харагдана (жишээ нь `biome IN ('Semi Desert') AND treatment IN ('Post rehab')`).
3. **Газрын зураг ↔ график ↔ хүснэгт хоорондоо холбоотой**
   - Графикийн багана дээр дарвал тухайн утгаар шүүлтүүр нэмэгдэж, бүх хэсэг дахин
     ачаалагдана.
   - Ургамлын зүйлээр шүүхэд эхлээд `bichiglel` / `lpdata` хүснэгтээс тухайн зүйл
     бүртгэгдсэн талбайн `globalid` ялгаж, дараа нь `survey` давхаргыг хязгаарлана
     (ArcGIS-ийн холбоост шүүлтийн зарчим).
   - Газрын зураг эсвэл хүснэгтийн мөр дээр дарвал тухайн талбай сонгогдож, KPI,
     график, хүүхэд хүснэгтүүд зөвхөн уг талбайн мэдээллээр шинэчлэгдэнэ.
4. **Хүснэгтийн удирдлага** — багана нуух/харуулах (тохиргоо хөтөч дээр хадгалагдана),
   эрэмбэлэх, хуудаслах. «10 минутын бичиглэл», «LP data» хүснэгтэд системийн
   багануудыг анхнаасаа нуусан.
5. **Нэршил** — талбарын нэрийг ArcGIS сервис дээр бүртгэгдсэн **alias**-аар нь
   харуулна (`Plot ID`, `Soum Name`, `Зүйл`, `Овог`, `Амин хэлбэр` гэх мэт). Ургамлын
   зүйл, ангиллын утгыг (`Post rehab`, `Control`, `Desert steppe`, `Bare ground`,
   `Litter`) орчуулахгүй, эх хэлбэрээр нь үлдээнэ. Alias байхгүй талбарт л дотоод
   толь ([src/lib/terms.ts](src/lib/terms.ts)) ашиглана.

## Тооцооллын арга зүй

Хэмжилтийн бодит бүтэц (2026 оны 7 сарын мэдээгээр):

- `lpdata` — талбай тус бүрт **4 шугам × 120 цэг = 480 цэг** (0.25 м алхамтай, 30 м урт
  шугам). `lpdataID_1` талбар нь шугам дээрх байршил (м), `speciesLP` талбарт тухайн
  цэгт таарсан ургамлын зүйл эсвэл `Bare ground` бичигдэнэ. `zai` талбар маягтад
  бөглөгдөөгүй тул ашиглаагүй.
- `bichiglel` — 10 минутын бичиглэл: талбай бүрийн зүйлийн жагсаалт (дунджаар 12 зүйл).

Үүнд тулгуурлан:

- **Ургамлан бүрхэц, %** — шугам-цэгийн нийт цэгээс ургамал тохиосон цэгийн эзлэх хувь
  (`Bare ground`, `Litter` — ургамал бус).
- **Зонхилох зүйл** — LP data-д таарсан цэгийн давтамжаар.
- **Зүйлийн баялаг** — 10 минутын бичиглэлээр бүртгэгдсэн зүйлийн тоо (талбайд ногдох дундаж).
- **Хувилбарын харьцуулалт** — нөхөн сэргээлтийн дараах ба хяналтын талбайн бүрхэцийн
  хувийг цэгийн нийлбэрээр тооцож зэрэгцүүлнэ.
- **Бүрхэцийн тархалт** — талбайн бүрхэцийн хувийг ангилсан гистограм.

## Гүйцэтгэлийн шийдэл

`lpdata` хүснэгт 56 мянга гаруй мөртэй тул:

- Графикийн үзүүлэлтийг **ArcGIS-ийн бүлэглэсэн статистикаар**
  (`groupByFieldsForStatistics` + `outStatistics`) серверийн талд тооцно — зүйлээр,
  талбайгаар, ургамалтай цэгээр тус тусад нь.
- Хүснэгтэд эхний 5,000 мөрийг татаж, нийт тоог тэмдэглэн харуулна. Талбай сонгоход
  тухайн талбайн **бүх бичлэгийг** `/api/arcgis/plot` замаар бүрэн татна.
- Хуудаслалтыг зэрэгцээ (concurrency 6) гүйцэтгэнэ.

Үр дүнд нэг хүсэлтийн хэмжээ 21 МБ → **1.3 МБ**, хугацаа 22 сек → **3 сек** болов.

## Газрын зураг

**ArcGIS Maps SDK for JavaScript** (`@arcgis/core`) дээр бүтээв.

- Анхдагч суурь зураглал — **хиймэл дагуулын зураг (satellite)**.
- **Esri-ийн basemap gallery** widget (Expand товчоор нээгдэнэ): хиймэл дагуул,
  хиймэл дагуул + нэршил, байр зүй, гудамж, хар/цайвар саарал, газрын гадарга,
  далай, OpenStreetMap — бүгд монгол нэршилтэй, API key шаардахгүй.
- **Тэмдэглэгээ** — төслийн үндсэн ангиллаар (Post rehab: `treatment`, Rangeland:
  `biome`) эсвэл ургамлан бүрхэцээр (5 ангилал, цэгийн хэмжээ бүрхэцтэй пропорциональ).
- Цэг дээр дарж талбай сонгоход KPI, график, хүүхэд хүснэгтүүд тухайн талбайд тохирно.
- Байршил нь `0,0` буюу бүртгэгдээгүй талбайг зурагт харуулахгүй, тоог нь тайлбарт
  шар өнгөөр анхааруулна.
